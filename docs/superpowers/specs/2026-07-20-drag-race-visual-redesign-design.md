# Редизайн визуала «Драг-заезда» — дизайн-спека

Дата: 2026-07-20. Статус: одобрено юзером (брейншторм 20.07: подход «арт-слои + вырезка», сеттинг «закатный город», прозрачные голуби — везде).

## 1. Проблема

Текущая сцена заезда (`public/js/catdrag.js`, задеплоена 15.07) выглядит дёшево:

1. **Арт голубей `/img/pigeons/*.webp` — с запечённым белым фоном.** На тёмной трассе едут белые квадраты; в карточках сетапа и всей голубятни (альбом, обмены, почта, дроп-попап) — те же белые квадраты.
2. **Процедурный фон не читается:** «скайлайн» — едва видимые прямоугольники, «облака» — тёмные кляксы, столбы — палочки. Нет ощущения скорости (ни спидлайнов, ни частиц, ни анимации спрайта).
3. **Полэкрана пустоты:** высота канваса фикс (58px/дорожка + 46), остальное — чёрный фон.
4. **Финиш:** голуби застывают обрезанными у правого края; плашка результата висит на пустоте.

Сетап-экран структурно рабочий (режим/ставки/CTA) — меняется только вид карточек.

## 2. Скоуп

**Только клиент + ассеты.** Сервер (`src/drag.ts`), API-контракты (`/api/pigeons/drag/*`), формулы, античит-замер тапа — НЕ трогаем. Изменяемые файлы: `public/js/catdrag.js` (+ его CSS внутри), файлы арта в `public/img/`, кэш-бастеры в `game.html`/`index.html` и ссылках `/img/pigeons/` (catdove.js, catclick.js).

## 3. Ассеты

### 3.1 Вырезка 17 голубей (прозрачный фон)

- Инструмент: rembg 2.0.76 (Python 3.11, сессия `u2net`) — паттерн `scripts/vasily-rembg-all.py`.
- Вход: текущие `public/img/pigeons/<breed>.webp` (512², белый фон). Выход: **те же пути**, webp c альфой, 512²: bbox-кроп по альфе (порог ~20), вписать в квадрат с полем ~6%, центрировать по горизонтали, прижать к низу с небольшим отступом (единая базовая линия для трассы и карточек).
- Обработка краёв: alpha-matting rembg; при белом ореоле — decontaminate (сдвиг цвета краевых полуальфа-пикселей от белого) или лёгкая эрозия альфы на 1px.
- Новый скрипт: `scripts/pigeon-art/cutout-all.py` (одноразовый, коммитится).
- **Кэш-бастер `?v=1 → ?v=2`** во ВСЕХ ссылках `/img/pigeons/`: `catdrag.js` (artSrc), `catdove.js` (~7 мест), `catclick.js` (дроп-попап). Проверка: `grep -n 'img/pigeons' public/` не находит `v=1`.
- Контроль качества: контактный лист 17 вырезок на тёмном и светлом фоне (глазами) — ни у одной не отъедены лапы/хвост/клюв, нет белой каймы.

### 3.2 Фоновые слои трассы (генерация)

Сеттинг: **закатный город в бренд-палитре** (золото `#f0c24e`, карамель, шоколад; тёплое закатное небо). Стилистика — та же мягкая 3D-иллюстрация, что арт голубей (Nano Banana), без фотореализма.

- **`public/img/drag/sky.webp`** — закатное небо с тёплыми облаками, без земли/зданий. Параллакс ×0.2.
- **`public/img/drag/city.webp`** — силуэтная лента города на прозрачном/градиентном низе: крыши, трубы, провода с сидящими птичками, вывеска «МАРИЯ» на одном из зданий (латиницей не писать), тёмный шоколадный силуэт с золотыми окнами. Параллакс ×0.5.
- Генерация: `scripts/pigeon-art/gemini-nbp-driver.mjs` (Gemini app по CDP, грабли в reference памяти: фокус-эмуляция, клик по кнопке отправки, blob через canvas). Генерим широкие кадры (≥1536px), в посте — **mirror-tile** (sharp: кадр + зеркальная копия встык) для бесшовного горизонтального зацикливания.
- Вес: суммарно ≤300 КБ (webp q~80, sky можно 1024×512, city — 2048×~400).
- **Fallback (если генерация недоступна/кредиты):** редизайн НЕ блокируется — временно рисуем небо/город улучшенной процедуркой (богатый закатный градиент + двухслойный силуэт с окнами), файлы слоёв подключаем позже. Решение о fallback принимается по факту, в спеке зафиксирован лишь порядок: сцена не должна зависеть от наличия файлов (graceful onerror → процедурный слой).

## 4. Сцена заезда (canvas)

### 4.1 Композиция

- Канвас занимает **всю высоту** `.cd-drag-race` (flex:1 оверлея), а не фикс-полоску. Горизонт (`groundTop`) ≈ 38–42% высоты: сверху небо+город, снизу дорога с дорожками.
- Дорожки: тёплый тёмный асфальт с лёгким градиентом глубины (дальняя дорожка чуть темнее), золотая пунктирная разметка (как сейчас, но аккуратнее), лёгкая виньетка по краям канваса.
- Камера: как сейчас — якорь лидера на ~40% ширины. **Финальный кадр:** камера доводится так, чтобы финишная арка стояла на ~72% ширины и ВСЕ голуби остановились у линии в кадре (не обрезаны справа).

### 4.2 Параллакс

- sky ×0.2, city ×0.5, дорога/разметка/арка ×1.0. Слои — pre-render в offscreen-canvas при инициализации (тайл повторяется по X), в кадре — только `drawImage` со сдвигом. onerror слоя → процедурная отрисовка того же слоя (см. 3.2 fallback).

### 4.3 Голуби и ощущение скорости

- Спрайты — новые прозрачные вырезки; зеркалить не нужно (арт смотрит вправо — проверить, при необходимости flip при отрисовке).
- Анимация спрайта: наклон вперёд пропорционально текущей скорости (~до 10°), вертикальный боб (как сейчас) + **squash-stretch** «взмах» (масштаб по Y ±4% в противофазе бобу).
- Частицы: пыль/пёрышки за каждым бегущим голубем (2–3 частицы/кадр у лидеров, пул ≤80 объектов, переиспользование). Свой голубь — золотое свечение (как сейчас) + чуть плотнее частицы.
- Спидлайны: при фазе гонки — редкие горизонтальные штрихи по всему кадру (прозрачность ~0.1), скорость ×1.4 мира.
- Тень-эллипс под голубем остаётся (на земле, без боба).

### 4.4 Старт и отсчёт

- Отсчёт 3-2-1-GO переоформляется в **драг-«ёлку»**: DOM-плашка со столбиком из трёх красных огней (загораются по одному на 3/2/1) и зелёным на «СТАРТ!». Цифры остаются рядом (крупно, как сейчас).
- На «СТАРТ!» — короткая встряска камеры (±3px, 250мс) и вспышка частиц на старте.
- Логика замера реакции (armTap/onTap/таймаут 3000мс) — без изменений.

### 4.5 Читаемость гонки

- **Прогресс-бар** вверху канваса: тонкая линия трассы с точками-позициями всех участников (мой — золотая точка крупнее), обновляется каждый кадр.
- **Бейдж места** появляется над голубем в момент пересечения финиша («1», «2»…, мой — золотой).

### 4.6 Финиш и результат

- Финиш: **чекер-арка** (две стойки + перекладина в шашечку) вместо плоских квадратиков; при пересечении лидером — чекер-флаг-взмах (простая анимация перекладины не обязательна, достаточно статичной арки + частицы).
- Конфетти при моём 1 месте (частицы из верха кадра, 1.5с).
- Плашка результата: редизайн — **мини-подиум топ-3** (спрайты на пьедесталах 2-1-3 с местами) + крупно моё место и выигрыш/потеря монет (цвета pos/neg как сейчас), кнопки «Ещё раз»/«Закрыть» без изменений. Плашка поверх застывшего финального кадра (уже не пустота — сцена на весь экран).

### 4.7 Перф и доступность

- Цель 60fps на средних телефонах: слои pre-rendered, частицы из пула, никаких тяжёлых фильтров/шейдеров, `shadowBlur` — только у своего голубя (как сейчас).
- `prefers-reduced-motion`: без частиц, спидлайнов и встряски; параллакс и позиции остаются.
- DPR-скейлинг как сейчас (`setTransform(dpr…)`).

## 5. Сетап-экран

- Карточки соперников и «мой боец»: прозрачный арт на **градиентной подложке цвета редкости** (мягкий радиальный градиент: common — серый, rare — бронза, epic — фиолет, legendary — золото; тона существующих рамок `data-r`). Белых квадратов не остаётся.
- Остальная структура (режим/ставки/подсказка/CTA) — без изменений.

## 7. Риски

- **Генерация слоёв через Gemini CDP хрупкая** (вкладка/логин/кредиты) → fallback 3.2, не блокирует остальное.
- **rembg может съесть тонкие детали** (лапки) → контактный лист, при браке породы — ручной подбор параметров alpha-matting для неё.
- **Кэш старого арта у клиентов** → бамп `?v=2` обязателен во всех местах одновременно с заменой файлов; версии `catdrag.js?v=1→v=2` в `game.html` И `index.html` синхронно (правило проекта).
- Каталожный прокси `/img` с диск-кэшем на VPS касается только фото каталога 1С — `public/img/pigeons/` раздаётся статикой Express, инвалидация не нужна (проверить при деплое, что отдаётся новый файл).
