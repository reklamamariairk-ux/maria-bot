# Драг-рейсинг «Голубиные гонки» — дизайн

Дата: 2026-07-15. Статус: дизайн одобрен устно. Отдельный режим поверх голубятни/тюнинга (`2026-07-15-pigeon-tuning-divisions-design.md`). НЕ трогает недельную гонку/дивизионы.

## Цель

Дать визуальный интерактивный драг-заезд (в духе Subway Surfers / ВК-гонки): реакция на старте + мощность голубя (тюнинг) решают исход. Отдельный always-available режим, монетизирует прокачку и энергию, не ломает недельную гонку.

Решения (с пользователем):
- **Отдельный режим** (не заявка недельной гонки; недельная гонка не меняется).
- **Мощность главнее реакции**: реакция даёт фору на старте, решает только близкие дуэли; сильный голубь отыграет любую фору.
- **Призраки = голуби реальных игроков**, подобранные по мощности; при нехватке живых — синтетика под уровень.
- **Два подрежима**: 🏁 Тренировка (только энергия, без ставок) и 💰 Заезд на ставку (энергия + ставка монетами, выигрыш/потеря).
- **Античит**: исход считает сервер; реакция зажимается; ставка/энергия — в транзакции.

## Механика заезда

### Ход времени
1. Клиент: обратный отсчёт 3-2-1-**GO**, замеряет реакцию `reactionMs` = задержка тапа после GO.
2. Один серверный вызов резолвит заезд (см. API): по реальному тюнингу голубя из БД + зажатой реакции + серверному RNG считает **финишное время** каждого гонщика.
3. Клиент анимирует заезд так, чтобы каждый голубь пришёл к ленте ровно в своё `finishT` (позиции интерполируются). Победа/место — из серверного результата.

### Формула (сервер, чистая, тестируемая)
Для гонщика:
```
power   = 6*tune_speed + 6*tune_stamina + RARITY_BASE[rarity] + 4*(stars-1)   // как в raceScore, но детерминированно
speed   = BASE_SPEED + power * SPEED_PER_POWER          // выше мощность → выше топ-скорость
reactDelay = clamp(reactionMs, 120, 3000) / 1000 * REACT_WEIGHT   // фора: меньше реакция → меньше задержка
luck    = r * LUCK_SPREAD                                // маленький рандом (r∈[0,1) серверный)
finishT = TRACK / speed + reactDelay + luck              // секунды; меньше = выше место
```
Веса подобраны так, что **мощность доминирует** над реакцией: разница в 1 уровень тюнинга перевешивает почти идеальную реакцию; реакция решает при близкой мощности. Точные константы — в конфиге, калибруются на тесте.

Чистые функции (vitest без БД):
- `dragPower(rarity, stars, speed, stamina): number`
- `dragFinishTime(power, reactionMs, r): number`
- `resolveRace(racers: {power, reactionMs, r}[]): {index, finishT}[] отсортировано` — места по возрастанию finishT.

### Реакция игрока-призрака
У каждого игрока храним `race_reaction_ms` (последняя/типичная реакция) в `clicker_state` — призрак «оживает» из его реального тюнинга + этой реакции. Нет значения → синтетическая реакция под уровень.

## Соперники (matchmaking по мощности)

- Целевая мощность = мощность выбранного голубя игрока.
- SELECT из `pigeon_inventory` других игроков (`chat_id <> me`, `count>0`), мощность которых в коридоре ±POWER_BAND, `ORDER BY |power - target|`, LIMIT 3.
- Если живых < 3 — добить **синтетическими** гонщиками: случайная порода-под-редкость + тюнинг, дающий мощность ≈ target ± небольшой разброс, синтетическая реакция. Помечаются `bot:true` (в UI без имени, просто «Соперник»).
- Матч по мощности делает ставку честной борьбой (реакция+рандом при равной силе), а не краном монет для китов.

## Экономика

- **Энергия**: каждый заезд (тренировка и ставка) стоит `DRAG_ENERGY_COST` (напр. 250) энергии кликера — естественный лимитер, привязка к экономике кликера. Нет энергии → «Подожди восстановления».
- **Ставка** (только режим bet): игрок выбирает ставку из пресетов (в пределах баланса). Выплата по месту:
  - 1 место → `+stake` net (получаешь 2×stake),
  - 2 место → возврат ставки (0),
  - 3–4 место → `−stake`.
  Матч по мощности + доминирование мощности → хорошо прокачанный чаще в топе, но не гарантированно (реакция+рандом). Не кран: 2-е = возврат, ожидание при равной силе близко к нулю. Константы выплат — тюнятся.
- Тренировка: ставки нет, монеты не начисляются/не теряются — только практика.

## Данные

```sql
ALTER TABLE clicker_state ADD COLUMN IF NOT EXISTS race_reaction_ms SMALLINT;  -- последняя реакция игрока (для призраков/статы)
```
Отдельных таблиц не нужно: результат заезда не хранится (мгновенная сессия), призраки собираются на лету из `pigeon_inventory`. Ставка/энергия/выплата — апдейты `clicker_state`.

## API (routes/pigeons.ts)

| Метод | Путь | Тело | Что делает | rateLimit |
|---|---|---|---|---|
| POST | /api/pigeons/drag/opponents | `{breed}` | подобрать 3 соперников под мощность (для превью перед стартом) | 30 |
| POST | /api/pigeons/drag/race | `{breed, mode:'training'\|'bet', stake?, reactionMs}` | транзакция: списать энергию (+ставку для bet), собрать соперников, посчитать результат, рассчитать выплату, вернуть заезд | 20 |

Ответ `/race`: `{ racers: [{breed, power, finishT, me, bot}], myPlace, reward, mode, newBalance, newEnergy, reason? }`. Ошибки (400 `{error}`): `not_owned`, `no_energy`, `not_enough_coins`, `bad_stake`, `bad_mode`.

Серверная логика — в новом `src/drag.ts` (чистые функции + `pickOpponents` + `runRace`), чтобы не раздувать `pigeons.ts`.

### Античит
- `reactionMs` зажимается в `[120, 3000]` мс (человеческая реакция; идеальный ноль невозможен).
- `power` берётся ТОЛЬКО из БД (реальный тюнинг), клиент не влияет.
- Энергия и ставка списываются в ТОЙ ЖЕ транзакции, что резолв — нет «ретрая до победы» (каждый вызов стоит энергию+ставку и возвращает серверный исход).
- Обновление `race_reaction_ms` игрока = зажатое значение.

## Клиент (новый `public/js/catdrag.js`, вход из секции гонки в catdove.js)

- Кнопка **«Драг-заезд»** в секции «Гонка стаи» коллекции (рядом с недельной заявкой) → открывает полноэкранный оверлей драга.
- Экран выбора: свой голубь (owned, показывает мощность/дивизион), режим (Тренировка / Ставка), для ставки — выбор суммы; превью соперников (`/opponents`).
- Заезд: сайд-скролл-трасса (canvas), 3-4 дорожки, спрайты голубей = существующие webp-карточки (`/img/pigeons/{breed}.webp`), фон-парковка/улица в бренд-палитре. Отсчёт 3-2-1-GO, тап на GO, замер реакции → POST `/race` → анимация по `finishT` (камера едет за лидером) → лента финиша → плашка места + выигрыш/потеря.
- Всё серверное списание отражается: `newBalance`/`newEnergy` в стейт кликера (мост `window.ck*`).
- Reason-коды в тосты (`no_energy`→«Не хватает энергии», `not_enough_coins`→«Не хватает монет на ставку»).
- Bump версии, подключение в game.html/index.html как catdove.js.

## Приёмка

1. dragPower/dragFinishTime/resolveRace — чистые (vitest): мощнее голубь → меньше finishT; идеальная реакция НЕ перебивает большую разницу мощности; при равной мощности реакция решает. (vitest)
2. Матч соперников: подбираются по мощности в коридоре; при <3 живых добиваются ботами. (E2E на VPS)
3. `/race` training: списывает энергию, монеты не трогает, возвращает место. (E2E)
4. `/race` bet: списывает энергию+ставку, при 1 месте начисляет 2×stake, при 3-4 — теряет; без энергии→no_energy, без монет→not_enough_coins. Атомарно. (E2E)
5. Античит: reactionMs=0 зажимается до 120; результат берёт power из БД. (vitest+E2E)
6. tsc + vitest зелёные; смоук прода; ручной прогон заезда в браузере (визуал).

## Чего сознательно НЕТ (YAGNI)

Реалтайм-PvP (записанные призраки вместо живых), запись тап-по-тапу (призрак выводится из тюнинга+reaction), реальные деньги/вывод, апгрейд трасс, кастомизация дорожек, турнирные сетки. Только два режима + матч по мощности.
