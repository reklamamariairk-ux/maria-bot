# Драг-заезд v3: механика «Тап-заезд»

**Дата:** 2026-08-04 · **Причина:** решение юзера — «сделать чтобы гонка зависела от того,
сколько раз тапнешь». Предыстория: v2 «Идеальный запуск» весь навык держал ДО старта
(прогрев+реакция, дальше кино), а исход решала мощность (деньги), не игра. Плюс два бага
характеристик: `speed` и `stamina` в `dragPower` взаимозаменяемы (6·speed+6·stamina),
а `luck` в драге вообще мёртв (не входит ни в мощность, ни в финиш-тайм).

## Что меняем и зачем
1. **Исход зависит от тапов во время заезда** — актив весь заезд, а не одно касание.
2. **Три характеристики разведены по РОЛЯМ** (было: 2 одинаковы, 1 мёртвая):
   - **Скорость** → крейсерский темп (пол результата даже без тапов).
   - **Выносливость** → эффективность тапов: сколько тапов нужно до максимума (больше стамины → меньше тапать за тот же максимум = «каждый взмах толкает дальше»).
   - **Удача** → стабильность: сжимает случайный разброс (лучший worst-case). Оживает.
3. **Анти-чит ставок сохраняется** структурно: тап-навык ∈ [0,1] встаёт в тот же слот
   `skill`, что и запуск v2 → доказанная Монте-Карло защита переносится (идеальный
   скилл=1.0 против поля U[0.75,1.0] → EV ≤ 0). Автокликер = случай skill=1.0 = EV ≤ 0.

## Игровая петля (клиент)
1. Ёлка 3-2-1-зелёный (оставляем — момент реакции + фидбек фальстарта «Рано!»).
2. На зелёный **открывается тап-зона на весь заезд** (~5с, `TAP_WINDOW_MS`). Тапай как можно
   чаще — каждый тап живо толкает твоего голубя вперёд (счётчик тапов + спидометр).
3. Финиш: места server-authoritative, но живой прогресс МОЕГО голубя ведут тапы (juice).
   Боты анимируются по своему серверному finishT.
4. Результат-брейкдаун: «Тапов: 47 · темп 91% · старт 0.28с» — видно, что улучшать.

## Сервер (src/drag.ts) — модель v3
Payload: `{ breed, mode, stake, tap: { count, reactionMs, durationMs } }` — всё untrusted.

- **Клампы**: `durationMs` → [3000, 8000]; `count` → [0, TAP_RATE_CAP·durationMs/1000]
  (RATE_CAP ≈ 12 тапов/с — потолок выше человеческого, но скрипту не даёт бесконечность);
  `reactionMs` как в v2 (Math.max(0)·|| 3000, clampReact 200..3000).
- `tapTarget(stamina) = TAP_TARGET_BASE − TAP_TARGET_PER·stamina` (48 → 28 при стамине 0..10).
- `tapAccuracy(count, stamina) = clamp01(count / tapTarget(stamina))`.
- `tapSkill(tap, stamina) = TAP_W·tapAccuracy + (1−TAP_W)·reactAccuracy(reactionMs)`, TAP_W = 0.7
  (тапы главнее, реакция — меньшая доля + защита от фальстарта).
- `cruisePower(rarity, stars, speed) = RARITY_BASE + 4·(stars−1) + 6·speed` — БЕЗ стамины.
- `matchPower = cruisePower + 6·stamina` = прежний `dragPower` (матчмейкинг/дивизионы/боты
  НЕ трогаем — коридор ±POWER_BAND, makeBot, недельная гонка остаются как есть).
- `luckSpread(luck) = LUCK_SPREAD_V2·(1 − LUCK_TIGHTEN·luck/TUNE_MAX)`, LUCK_TIGHTEN = 0.5
  (удача 10 → разброс вдвое уже).
- `dragFinishTimeV3(cruisePower, tapSkill, luck, r) =
     TRACK/(BASE_SPEED + cruisePower·SPEED_PER_POWER) + (1−tapSkill)·SKILL_SPREAD + r·luckSpread(luck)`.
- Поле «Ставки»: `hardenBetFieldV3` — слабее target−BET_POWER_GAP (по matchPower) → бот ≈target;
  **tapSkill соперников раздаёт сервер** U[COMP_SKILL_LO, COMP_SKILL_HI]; «Тренировка» — шире/добрее.
- Обратная совместимость: `tap`-объект → v3; иначе `skill` → v2; иначе reactionMs → v1 (не удаляем).
- `race_reaction_ms` пишем из `tap.reactionMs` (легаси-подбор соперников продолжает жить).
- Ответ + `mySkill:{ taps, tapAcc, react, total }` для брейкдауна.

## Цели баланса (Монте-Карло в tests/drag.test.ts — паттерн v2)
- Идеальный тап-скрипт (tapSkill=1.0) в «Ставке» — EV ≤ 0 (казна не кормит автокликер).
- Честный хороший заезд (~0.8) — EV в −5..−45% ставки.
- Навык значим: EV(0.85) − EV(0.4) > 0.3 ставки.
- При равном крейсе выше tapSkill → раньше финиш (без люка).
- Разведение статов: при равном matchPower голубь с бо́льшей стаминой достигает того же
  tapSkill меньшим числом тапов; голубь с бо́льшей скоростью быстрее на нулевых тапах;
  бо́льшая удача → у́же разброс времени.

## Что НЕ трогаем
Анимация подиума, ставки/выплаты (PAYOUT), энергия (DRAG_ENERGY_COST), транзакционная
модель runRace, недельная «Гонка стаи» (raceScore в pigeons.ts), тюнинг-цены. Меняется
только ЧТО клиент честно измеряет (число тапов вместо отступов свипа) и роль 3 статов.
