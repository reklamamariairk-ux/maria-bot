# «Голубиная почта» — P2P-обмен и коллекция пород голубей в «Котик Комбат»

Дата: 2026-07-14. Статус: дизайн одобрен устно (подход A, награды v1 — только игровые).

## Цель

Дать игрокам повод взаимодействовать друг с другом (общение + обмен) внутри игры, не создавая
модерационной нагрузки и фрод-каналов. Форма: коллекционные породы голубей с редкостью,
обмен «птица-на-птицу» и «голубиная почта» со стикер-фразами Василия.

Ключевые решения (зафиксированы с пользователем):
- Товар рынка — **голуби** (игровой ресурс, БЕЗ реальной ценности в v1).
- Коммуникация — **структурная**: стикер-фразы Василия, никакого свободного текста → ноль модерации.
- Награды за сеты в v1 — **только игровые** (монеты, бейджи, игровой перк). Реальные призы
  (баллы/купоны через вехи) — потенциальный v2 после ответов Маши по опроснику наград.
- Масштаб аудитории неизвестен → стартуем с обменов 1-на-1 и почты; биржа за монеты —
  осознанно НЕ делается (фрод-канал перекачки монет между аккаунтами + риск пустой витрины).

## Контекст кодовой базы

- «Голуби» сейчас = 16 бизнес-карт-помощников (`BUSINESSES`, вкладка «Голуби» в navbar,
  нейроарт-набор v6). Коллекция = level>0 по категории (`ACHIEVEMENTS col_*`, `MILESTONES ms_col_*`).
  **Эта механика не трогается** — новый слой живёт рядом.
- Экономика целиком на сервере (`src/clicker.ts`), таблицы создаются в `ensureSchema` там же,
  ключ игрока — `chat_id BIGINT` (VK-игроки через ID-сдвиг 2e12, платформа-агностично).
- Транзакции: `pool.connect()` + BEGIN/COMMIT/ROLLBACK + release в finally (НЕ `pool.query("BEGIN")`).
- Дедуп выдач — вставка строки-мьютекса (паттерн `clicker_gifts`).
- Сутки считаются по Иркутску (`todayIrkutsk()`).
- Роуты: `src/routes/*.ts` с `requireTgUser` + `rateLimit(n)`.
- Клиент: отдельные модули в `public/js/` с версией для cache-bust.

## Механика

### Породы (16 карточек, 4 сета × 4)

| Сет | Породы | Редкость |
|---|---|---|
| Городские | Сизарь, Белобокий, Рябой, Чубатый | 4× обычная |
| Кондитерские | Ванильный, Шоколадный, Карамельный, Ягодный | 4× редкая (зеркалят 4 команды-сквада) |
| Почтовые легенды | Иркутский почтарь, Байкальский гонец, Ночной курьер, Вожак стаи | 4× эпик |
| Праздничные | Свадебный, Именинный, Снежный, Золотой голубь Василия | 3× эпик, Золотой = легендарный |

Веса дропа по редкости: обычная 70% / редкая 20% / эпик 8% / легендарный 2%.
Конкретная порода — равновероятно внутри редкости. Дубликаты копятся счётчиком.

Названия/состав пород — черновик, можно править при генерации арта без изменения кода
(конфиг-массив `PIGEON_BREEDS` в `clicker.ts` по образцу `BUSINESSES`).

### Источники дропа (встраиваются в существующие ежедневки, новых таймеров нет)

- **Сундук удачи**: новый тип приза «голубь», шанс ~35% (перебалансировать веса `CHEST_PRIZES`).
- **Комбо дня** собрано → гарантированный дроп (усиливает и так сильную механику).
- **Первый claim мини-игры за день** (`claimGame`): шанс 25% (одна попытка/день независимо от числа игр).
- **Золотой котик**: шанс 5%.

Все дропы — внутри существующих серверных транзакций этих механик; клиенту возвращается
`pigeonDrop: {breed}` в ответе для анимации «прилетел голубь».

### Альбом и награды за сеты (v1 — только игровое)

- Собран сет из 4 пород → монеты: Городские 25 000, Кондитерские 50 000, Почтовые 75 000,
  Праздничные 100 000 + бейдж сета в профиле.
- Полный альбом 16/16 → титул «Голубиный барон» (показывается в лидерборде рядом с именем)
  + постоянный перк **+5% к пассивному доходу**.
- Награда за сет выдаётся один раз (строка-мьютекс `pigeon_sets_claimed`), пересборка после
  обмена последнего экземпляра повторно не награждается.

### Обмен 1-на-1 (рынок)

- Оффер: «отдаю породу X (только дубликат, count>1), хочу породу Y».
  Адресный (`to_chat_id`) или открытый (NULL) — открытые видны всем на доске обменов.
- **Эскроу**: при создании оффера экземпляр X списывается сразу; отмена/истечение возвращает.
- Принятие: атомарная транзакция (SELECT ... FOR UPDATE оффера + инвентаря акцептора),
  у акцептора Y тоже должен быть дубликатом. Правило одно и простое: **меняются только запасные**.
- Лимиты: максимум 3 активных оффера на игрока; TTL оффера 7 дней → авто-возврат (проверка
  лениво при чтении доски + в ежедневном кроне).
- Редкость обеих пород видна в UI оффера; ограничений «эпик только на эпик» нет — ценности
  в деньгах нет, а видимая редкость защищает от невыгодных обменов по незнанию.
- Имена на доске — как в лидерборде (та же приватность-модель).

### Голубиная почта (коммуникация)

- 1 отправка в день (по Иркутску): выбираешь **дубликата**, получателя и стикер-фразу Василия.
- Получатели на выбор: однокомандцы (мой сквад, активные за 7 дней), мои рефералы/реферер,
  или «случайному игроку» (случайный активный за 7 дней, исключая себя) — сюрприз незнакомцу.
- Стикер-фразы — 10 пресетов («Держи, пригодится!», «Сладкого дня!», «От Василия с любовью» и т.п.),
  свободного текста НЕТ.
- Получателю: карточка «Тебе прилетел голубь от {имя}» при входе + игровой пуш (в рамках
  существующего лимита 1 игровой пуш/день и тихих часов 22–9, `clicker-push.ts`).
- Ответ: кнопка «Поблагодарить» — ответный стикер (без птицы). На этом цепочка закрыта —
  переписки нет by design.

### Анти-абьюз

- Отдать (обмен/почта) можно только дубликат → последний экземпляр не потерять, сеты не разобрать в минус.
- Голуби не покупаются и не продаются за монеты → нулевой канал перекачки ценности между
  аккаунтами (критично на будущее, когда включится `REWARDS_ENABLED`).
- Rate-limit всех новых роутов; лимиты: 3 оффера, 1 почта/день.
- Все переходы владения — в транзакциях с FOR UPDATE; выдачи наград — через строки-мьютексы.
- Кэп на перк альбома: +5% фиксирован, не стакается.

## Данные

```sql
CREATE TABLE IF NOT EXISTS pigeon_inventory (
  chat_id BIGINT NOT NULL, breed TEXT NOT NULL,
  count INT NOT NULL DEFAULT 0, first_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  PRIMARY KEY (chat_id, breed));
CREATE TABLE IF NOT EXISTS pigeon_trades (
  id BIGSERIAL PRIMARY KEY, from_chat BIGINT NOT NULL, to_chat BIGINT,
  give TEXT NOT NULL, want TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'open',  -- open|done|cancelled|expired
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(), closed_at TIMESTAMPTZ, closed_by BIGINT);
CREATE TABLE IF NOT EXISTS pigeon_mail (
  id BIGSERIAL PRIMARY KEY, from_chat BIGINT NOT NULL, to_chat BIGINT NOT NULL,
  breed TEXT NOT NULL, sticker SMALLINT NOT NULL, thanks_sticker SMALLINT,
  sent_at TIMESTAMPTZ NOT NULL DEFAULT NOW(), seen_at TIMESTAMPTZ);
CREATE TABLE IF NOT EXISTS pigeon_sets_claimed (
  chat_id BIGINT NOT NULL, set_id TEXT NOT NULL, claimed_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  PRIMARY KEY (chat_id, set_id));
```

Индексы: `pigeon_trades (status, created_at)` для доски; `pigeon_mail (to_chat, seen_at)` для входящих.

## API (новый файл `src/routes/pigeons.ts`, логика в `src/pigeons.ts`)

| Метод | Путь | Что делает | rateLimit |
|---|---|---|---|
| GET | /api/pigeons | инвентарь + прогресс сетов + мои офферы + непрочитанная почта (счётчик) | 60 |
| POST | /api/pigeons/set-claim | забрать награду за собранный сет `{set}` | 20 |
| GET | /api/pigeons/trades | доска: открытые + адресованные мне | 60 |
| POST | /api/pigeons/trade | создать оффер `{give, want, to?}` | 20 |
| POST | /api/pigeons/trade/accept | `{id}` — атомарный своп | 20 |
| POST | /api/pigeons/trade/cancel | `{id}` — вернуть эскроу | 20 |
| POST | /api/pigeons/mail | `{breed, to: chatId|'random'|'squad:<id>', sticker}` | 10 |
| POST | /api/pigeons/mail/thanks | `{id, sticker}` | 20 |
| GET | /api/pigeons/mail | входящие (последние 30) + отметить seen | 60 |

Дроп-логика — внутри `clicker.ts` (openChest/claimCombo/claimGame/claimBonus), не отдельным роутом.

## Клиент

- Новый модуль `public/js/catdove.js` (v1) — не раздуваем catclick.js (242 KB).
- Вкладка «Голуби» получает переключатель секций: **Помощники** (текущий контент, без изменений)
  и **Коллекция** (альбом 16 карточек с редкостью, прогресс сетов, кнопки «Обмены» и «Почта»).
- Бейдж-счётчик непрочитанной почты на вкладке.
- Анимация дропа «прилетел голубь» — переиспользовать стиль попапов наград catclick.
- Арт: 16 карточек пород, тот же нейроарт-пайплайн, что «голуби-помощники v6» (Nano Banana,
  бренд-стиль). Генерация арта — отдельная задача; до готовности арта в коде — рамка-плейсхолдер
  с иконкой dove из `icons.js` (фича за арт-геттингом не блокируется).

## Чего сознательно НЕТ в v1

- Биржи/продажи за монеты (фрод-канал + пустая витрина при малом DAU).
- Свободного текста в любом виде.
- Реальных наград за сеты (ждёт решений Маши; задел: сет-награду легко переключить на веху).
- Командного общака (кандидат v2 вместе с командным зачётом).
- Telegram Stars, крипты, rewarded video.

## Приёмка

1. Дроп: открыть сундук/собрать комбо → голубь появился в альбоме, дубликат увеличил счётчик.
2. Сет: собрать 4 городских → кнопка «Забрать 25 000» работает один раз, бейдж появился.
3. Обмен: игрок A (2× Сизарь) создаёт оффер Сизарь→Ванильный; у A списался Сизарь; игрок B
   (2× Ванильный) принимает → у B −Ванильный +Сизарь, у A +Ванильный; повторное принятие → ошибка.
4. Отмена/TTL: отмена возвращает птицу; оффер старше 7 дней при чтении доски помечается expired и возвращает.
5. Почта: отправка дубликата случайному → у получателя карточка + птица; вторая отправка в день → отказ;
   отправить последний экземпляр → отказ.
6. Пуш о почте приходит в рамках дневного лимита и тихих часов.
7. Обе платформы: сценарии 3 и 5 работают между TG- и VK-игроком (chat_id со сдвигом).
8. `tsc` чистый; нагрузочно: доска с 1000 офферов отвечает <200мс.
