# Драг-рейсинг: закрытие EV-утечки ставки (fast-follow от 15.07)

Дата: 2026-07-30. Статус: принято (решения приняты автономно по feedback_no_questions, юзер правит постфактум).

## Проблема

Fast-follow #1 из спеки драг-рейсинга: режим «Ставка» имеет положительное матожидание
для читера, скриптующего константную реакцию. Подтверждено Монте-Карло (300k заездов,
поле равной мощности, текущие константы):

| Игрок | P(1 место) | EV ставки |
|---|---|---|
| читер 120 мс | 0.505 | **+24.9%** |
| честный быстрый 250 мс | 0.291 | −16.6% |
| средний 350 мс | 0.146 | −47.8% |

Корни (три независимых утечки одной семьи):
1. **Реакция**: клиент присылает `reactionMs`, сервер клампит от 120 мс; боты «реагируют»
   за 250–490 мс, сохранённые реакции реальных игроков — часто 400–1500 мс (казуалы).
   Константные 120 мс дают стабильные +0.03…+0.09 с при разбросе удачи всего 0.15 с.
2. **Мощность вниз**: подбор соперников ±25 power «ближайшие снизу тоже ок» — игрок
   на вершине лестницы получает поле строго слабее себя; 25 power ≈ 0.9 c → гарантированная победа.
3. **Потолок ботов**: `makeBot` строит ботов со `stars=1` → максимум 148 power, а прокачанный
   игрок (легендарка ★3 + тюнинг 10/10) имеет 156 → на эндгейме боты недосягаемы (EV ≈ +0.75).

## Решение (только сервер, `src/drag.ts`; фронт и выплаты не трогаем)

1. **`REACT_MIN` 120 → 200 мс** — общий кламп скоринга (игрок/соперники/боты).
   Честные быстрые тапы — 200+ мс; 120 мс человечески недостижимы (это предугадывание).
2. **Режим «Ставка»: реакции соперников раздаёт сервер** — конкурентная выборка
   `U[205, 325]` мс каждому сопернику (реальным и ботам) на каждый заезд. Порода и
   мощность реальных соперников остаются настоящими (флейвор сохранён), но их
   протухшая сохранённая реакция больше не превращает поле в кормушку.
   Тренировка — без изменений (ставок нет, сохранённые реакции живут для флейвора).
3. **Гард мощности в «Ставке»**: соперник с `power < target − 10` заменяется ботом
   ≈`target` — поле не может быть целиком слабее игрока.
4. **`makeBot` умеет звёзды 1→3**: редкость+звёзды поднимаются, пока тюнинга хватает
   дотянуться до target → бот достижим вплоть до максимума игрока (156).

Выплаты (2×/1×/0×) и UI не меняются: комбинация «floor 200 + конкурентное поле» уже
даёт нужную экономику.

## Целевая экономика (Монте-Карло 300k, поле равной мощности, новые константы)

| Игрок | P(1 место) | EV ставки |
|---|---|---|
| читер (кламп в 200 мс) | 0.355 | **−3.7%** |
| честный быстрый 250 мс | 0.270 | −20.4% |
| средний 320 мс | 0.170 | −42.1% |
| медленный 600 мс | 0.010 | −92.3% |

Читер не влияет на серверную выборку реакций поля → его долгосрочный EV = −3.7% (казна
в плюсе), при этом реакция осталась значимой: быстрый честный выигрывает чаще честной
доли 0.25 и заметно чаще медленного.

## Тесты (vitest, `tests/drag.test.ts`)

- Монте-Карло (200k): EV(реакция=0, т.е. идеальный скрипт) < −1%; EV(600мс) < −50%;
  EV(250мс) − EV(600мс) > 0.3 (реакция всё ещё навык).
- `hardenBetField`: реакции всех соперников в [205, 325]; слабый по мощности заменён
  ботом ≈target; соперник в допуске сохраняет породу/мощность.
- `makeBot(156)` достигает 156 ± 3 power.
- Обновление старого теста клампа 120 → 200.

## Вне скоупа

- Изменение выплат/ставок, UI catdrag.js, ЛЮБЫЕ правки вне игры (feedback_game_only_scope).
- Усреднение сохранённых реакций (не нужно: в ставке реакции соперников теперь серверные).
