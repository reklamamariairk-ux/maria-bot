## 1. Контекст и зачем

Фаза 1 «Дома кота» в проде с 07.07.2026: вкладка «Дом» в кликере открывает тамагочи
(`catpet.js`), стрик заботы начисляет монеты в единый кошелёк (`clicker_state.balance`).
Фаза 2 замыкает петлю «забота → реальная ценность»: подарки за вехи заботы и обмен
монет на реальные баллы карты клуба.

**Ключевые находки разведки (08.07):**

- **Лестница вех уже в проде и живая** (`GIFTS_ENABLED=true`, `src/clicker.ts MILESTONES`):
  уровни/коллекция/рефералы → реальные баллы (`earnPoints`) и купоны-товары
  (`grantRewardByCode`: −5%, −500₽, бенто). Клейм — `claimMilestone` с бронью в
  `clicker_gifts` (двойная выдача исключена), только подтверждённый телефон.
- **Ветка `flow2-monetization` (8 коммитов, opus-ревью пройдено, НЕ смёржена)** уже
  реализовала: чекаут гасит персональные коды `user_rewards`
  (`findUserReward`/`markUserRewardUsed` + ветки в `/api/promo/validate|use`) — keystone;
  `clicker.redeemReward` выдаёт реальный купон через `grantRewardByCode` с компенсацией
  монет при сбое; копи-кнопки кодов; `free_item`-коды не сжигаются за 0₽ (показ на кассе).
  Мёрж в текущий master — чистый (проверено `git merge-tree`, 0 конфликтов).
- **Живая дыра в проде:** вехи уже выдают купоны, которые чекаут пока НЕ умеет гасить
  (валидируется только `promo-codes.json`). Мёрж flow2 это чинит.
- **Монеты → баллы карты** (`REWARDS` `bonus300`, kind `loyalty`) не реализованы нигде:
  flow2 сознательно вынес этот путь за скоуп.
- `rewards_catalog` уже содержит `free_dessert` («Бесплатный десерт к торту от 2000₽»,
  `free_item`) — годится для вехи заботы.

## 2. Решения (зафиксированы в брейншторме)

1. **Скоуп Фазы 2 = 4 блока:** мёрж flow2 (фундамент) + обмен монет→баллы карты +
   вехи заботы с виджетом в «Доме» + перевод флага обмена в env.
2. **Подход:** ветка `dom-kota-phase2` от `origin/master`, первым шагом — мёрж
   `flow2-monetization` (сохраняем проведённое ревью), сверху новые блоки.
3. **Витрина = общая лестница:** вехи заботы добавляются в существующую лестницу
   «Награды за прогресс» (вкладка «Задания» кликера); в «Доме кота» — компактный
   виджет-тизер с переходом. Одна точка правды, без дубля витрины.
4. **Включение:** фикс чекаута — всегда вкл (починка бага); вехи заботы — живые сразу
   со скромными числами (как существующая лестница); обмен монет (купоны И баллы) —
   за env-флагом, выключен до решений Маши.
5. **Вехи заботы («длинная морковка», по рекорду стрика):**

   | Дней подряд (рекорд) | Награда |

## 4. Архитектура: три потока ценности на одной рельсе

Всё на существующей рельсе `user_rewards` + `rewards_catalog` (после flow2 чекаут её гасит).

### 4.1. Монеты → купон (из flow2, готово)

`clicker.redeemReward`: списание монет транзакционно + запись `clicker_redemptions`
(code `PENDING`) → `grantRewardByCode` вне tx → при сбое компенсация монет и чистка
PENDING. За флагом `CLICKER_REWARDS_ENABLED`.

### 4.2. Монеты → баллы карты (новое)

В том же `redeemReward` — ветка для `kind: "loyalty"` (`bonus300`, 300 баллов за
200000 монет — константа до решения Маши):

- проверки как у купонов: флаг, `REDEEM_PER_DAY`, баланс, `isPhoneVerified`
  (баллы падают на реальную карту — телефон обязателен);
- списание монет в транзакции + `clicker_redemptions` (code `POINTS-PENDING`);
- `earnPoints(chatId, points, "clicker_redeem", { reward: id })` вне tx;
- при сбое — та же компенсация монет, что у купонов;
- успех — код записи `POINTS:<n>`; фронту возвращается `{ ok, points }` (кода-купона нет).

### 4.3. Вехи заботы (новое)

- В `MILESTONES` — 5 вех с `cond: { type: "care_streak", target: 7|14|30|60|100 }`
  (награды — §2 п.5). Клейм — существующий `claimMilestone` (бронь `clicker_gifts`,
  телефон, points/perk-ветки уже есть).
- **Рекорд, а не текущее значение:** `care_streak` сбрасывается при пропуске дня; веха
  «7 дней подряд» должна оставаться достигнутой навсегда. Новая колонка
  `pet_state.care_streak_best INT NOT NULL DEFAULT 0` — обновляется при каждом
  инкременте стрика в `/api/pet/action` (`GREATEST(care_streak_best, care_streak)`).
  Backfill при миграции: `care_streak_best = GREATEST(care_streak, 0)`.
- **Проверка условия:** `msReached` сейчас считает только из `ClickerState`.
  Для care-вех `getMilestones`/`claimMilestone` дочитывают `care_streak_best` одним
  `SELECT` из `pet_state` (нет строки → 0) и передают в расширенный контекст условий.
- Вехи живые сразу после деплоя (под существующим `GIFTS_ENABLED=true`).

## 5. Env-флаг

- `CLICKER_REWARDS_ENABLED` (env): пустой/`0` = выкл (дефолт), `1` = вкл. Заменяет
  константу `REWARDS_ENABLED` в `clicker.ts`; фронт получает `enabled` из
  `/api/clicker/rewards` как сейчас (при выкл — витрина обмена скрыта/«скоро»).
- Гейтит ОБА обмена: монеты→купон и монеты→баллы.
- `GIFTS_ENABLED` остаётся `true` константой (вехи живут, как сейчас в проде).
- Числа (курсы обмена, цены в монетах, суммы вех) — константы в коде: при решениях
  Маши правим числа и включаем env; нового кода не потребуется.
- Документировать в env-файле VPS комментарием (не включать!).

## 6. Данные (изменения схемы)

```sql
ALTER TABLE pet_state ADD COLUMN IF NOT EXISTS care_streak_best INT NOT NULL DEFAULT 0;
UPDATE pet_state SET care_streak_best = GREATEST(care_streak, 0) WHERE care_streak_best = 0;
```

Additive, идемпотентно (UPDATE трогает только нулевые best). Новых таблиц нет:
`clicker_gifts`, `clicker_redemptions`, `user_rewards`, `rewards_catalog` уже есть.
Транзакции — только `pool.connect()` + client + BEGIN/COMMIT/ROLLBACK + release
в `finally` (правило проекта).

## 8. Ошибки и атомарность

- Списание монет и выдача ценности — в разных транзакциях (у `earnPoints`/
  `grantRewardByCode` свои pool-запросы) → **компенсация**: при сбое выдачи вернуть
  монеты и убрать PENDING-запись (паттерн flow2, переиспользуется для баллов).
- Двойной клейм вехи исключён бронью `clicker_gifts` (PK + `ON CONFLICT DO NOTHING`);
  при сбое выдачи бронь снимается (существующий код).
- `care_streak_best` монотонно не убывает (только `GREATEST`).
- Durable-возврат монет (Important #2 из ревью flow2 — компенсация может потеряться
  при падении процесса между COMMIT и компенсацией) — принимаем риск как flow2:
  вероятность мала, ущерб — монеты одного обмена; лог сбоя пишется.

## 9. Тестирование

Репо без тест-фреймворка: гейт — `tsc --noEmit` (бэк) + `node --check` (фронт),
смоук-скрипты как артефакты (`scripts/`, не коммитятся, гонять только с тестовыми
отрицательными `chat_id` + самоочистка — ⚠️ стейдж сидит на ПРОДОВОЙ Neon-БД).

Ключевые кейсы:

- **Вехи заботы:** достигается по рекорду (сброс текущего стрика не отбирает веху);
  двойной клейм → `already`; без телефона → `need_phone`; points-веха начисляет
  `earnPoints`, perk-веха пишет `user_rewards`.
- **Монеты→баллы:** списание+начисление; сбой `earnPoints` → компенсация монет;
  `REDEEM_PER_DAY` соблюдён; без телефона → отказ без списания.
- **Env-флаг:** пустой env → оба обмена `disabled`, витрина скрыта; `1` → работают.
- **Чекаут:** купон вехи проходит `/api/promo/validate` и гасится в `/use`
  (после мёржа flow2); `free_item` показывается на кассе, не сжигается за 0₽.
- **Регресс:** кликер (вкладки, лестница вех), «Дом» (уход/стрик/наряды), гость.
- **`care_streak_best`:** backfill идемпотентен; инкремент стрика тянет best вверх.

## 10. Риски и зависимости

- **Реальная ценность вех заботы уходит в прод сразу** (баллы 200–1000, купон −5%,
  десерт) — суммы скромные, в духе уже живой лестницы; финальное слово Маши может
  потребовать правку чисел (константы).
- **Мёрж flow2** чистый, но после него обязательный `tsc` + прогон ключевых сценариев
  (ветка отстала от master на весь «Дом кота»).
- **Стейдж = продовая БД** — мутирующие смоуки только с тестовыми chat_id.
- **Экономика монет** — цены обмена (100k–500k монет) заданы давно; при включении
  сверить с фактическим балансом игроков (аналитика кликера).
